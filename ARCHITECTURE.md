# ARCHITECTURE

A map of OPORD Analyst for a walkthrough, in the order the stops are worth visiting. Each
stop says what the piece does, why it exists, and what breaks if it is changed carelessly.
The rules live in `AGENTS.md`; this is the tour, with files and functions named so you can
jump to them.

**Safe to ignore.** `node_modules/` and `dist/` are installed and built output;
`package-lock.json` pins versions. Under `ios/`, `App/CapApp-SPM/` and `App/App.xcodeproj/`
are managed by Capacitor and Xcode, and `AppDelegate.swift`, `Info.plist` and the
storyboards are the Capacitor template (so is `SceneDelegate.swift`, except the one line
that creates `OPORDBridgeViewController`). The icons in `public/` and
`ios/App/App/Assets.xcassets/` are generated by `tools/make-icons.py`. None of it is
hand-written, and none of it is where a bug hides.

## 1. The whole app on one page: `AGENTS.md`, "Architecture & conventions"

There is no backend and no account. The device's `localStorage` is the database and the
schema is a naming convention: per-section notes are `inline-note-<id>`, checklists are
`pcc-*` and `pci-*`, the CASEVAC planner is one JSON document under `casevac-plan`. That is
what lets the app work with no connection and keep nothing anywhere else. The rule never to
rename or drop a key follows from it and is why notes survive updates: there is no server
copy, so a renamed key makes every user's notes vanish on the next deploy. A migration must
read the old shape and leave it readable (`normalizeChecklistItems`, `normalizePlan`).

## 2. The shell: `src/App.tsx`

One `view` state, saved as `active-view`, picks from the `NAV` list of five tabs. The header
holds the clock, the `TopCompass`, the blackout toggle (it sets `data-theme="blackout"` on
the page), the PDF and copy buttons (`exportPdf`, `exportText`) and `OperationManager` for
named plans. The toast listens for the `app-toast` event; the footer prints `buildStamp()`.
A shared `#cv=` link (`incomingPayload`) forces the CASEVAC tab open. A tab is a component
mounted while `view` matches, so there is no router and no URL state beyond that fragment.
Only one view is mounted at a time, which is why anything that must reach another tab goes
through storage (stop 3). A new tab must be added to `NAV` here and to the `DOCS` registry
in `exporters.ts`, or its PDF button throws.

## 3. How typing becomes saved text: `src/lib/storage.ts`, `src/lib/operationStore.ts`

`safeSetItem(key, value)` is the only correct way to write: it asks `operations.scopedKey`
for the physical key and turns a `QuotaExceededError` into the "Storage full" toast instead
of a crash mid-keystroke; `readItem` and `readNote` read through the same mapping.
`appendNote(id, text)` writes storage first and then fires `note-changed`, so INSERT INTO
ORDER works while the ORDER tab is not mounted. `OperationStore` keeps the plan index under
the key `operations`. The default plan keeps the original unprefixed keys, other plans
prefix theirs `op:<id>:<generation>:`, and `isOperationKey` says which keys belong to a
plan and which (`PREFERENCE_KEYS`) are device-wide. Mutations run under one Web Lock so two
tabs cannot corrupt the index; a reset changes the generation so a stale tab is refused;
`wipe()` commits a fresh generation before deleting anything. Named plans arrived after
people already had notes, so scoping by prefix instead of moving data meant an update
touched nothing. Writing with `localStorage.setItem` directly skips the scoping and the
quota guard, so text lands in the wrong plan. A per-plan key missing from `isOperationKey`
is shared across plans, left out of backups and survives a wipe.

## 4. Where the website and the iPhone app differ: `src/lib/native.ts`

`isNativeApp()` wraps `Capacitor.isNativePlatform()` and every difference sits behind it.
`saveBlob` hands a file to the iOS share sheet (`nativeShareFile`) in the app and triggers
a download on the web; the clipboard, shared links and the status bar have their own
functions here. `PUBLIC_SITE_URL` is where links shared from the app point, because the
app's own address means nothing on another device. Plugins are imported on demand, so the
website never downloads them. One build runs in two hosts, and this file is the whole list
of what they disagree about. A plugin called from anywhere else pulls native code into the
web build and can make the app silently do nothing; a download that never appears is the
usual sign. If something works on the web and not in the app, look here first.

## 5. Dictation end to end: `src/components/notes.tsx`, `ios/App/App/OPORDSpeechBridge.swift`

`useDictation` owns one DICTATE button. When `window.webkit.messageHandlers.opordSpeech`
exists, `toggleDictation` posts a `start` message with a `targetId` and `onDeviceOnly:
true`. In Swift, `OPORDSpeechBridge` is registered under that name by
`OPORDBridgeViewController.capacitorDidLoad`; it runs `SFSpeechRecognizer` with
`requiresOnDeviceRecognition`, refuses to start if the phone cannot do on-device English,
caps a take at 120 seconds and releases the microphone when the app backgrounds. Text
returns through `evaluateJavaScript` as an `opord-asr-result` event with `targetId`, `text`
and `isFinal`; the id comes from React's `useId`, so two buttons never cross-wire. Without
the bridge, the browser's Web Speech API is used, which may use the vendor's servers. The
split exists for OPSEC: in the app, audio never leaves the phone, and the guarantee is that
flag plus the refusal. Rename the handler or the event on one side and app dictation dies
quietly, because the web fallback still works and hides it. Remove the microphone and
speech usage strings from `Info.plist` and iOS kills the app at the first tap. Drop
`requiresOnDeviceRecognition` and audio goes to Apple.

## 6. Content is data: `src/content/rubric.ts`, `src/views/OrderView.tsx`

`RUBRIC` is the course grading sheet as data: sections of items with `id`, `label`, the
instructor `prompt` and `pts`, with `RUBRIC_TOTAL` (100) derived. `RubricChecklist` in
`GuideWidgets.tsx` renders it as the GUIDE rehearsal tracker (saved as `brief-rubric`) and
`guideDoc()` prints it. The ORDER tab lists the same graded blocks, but honestly: the
points in `OrderView.tsx` are typed into the JSX as `<Pts n={…} />`, and the TEMPLATE
outlines come from `src/content/templates.ts`, keyed by the same note ids. The idea is
that a new class's checklist is a data edit, not a code change; today that holds for the
tracker and the exports, while the ORDER points are a second copy, so changing one without
the other makes the tabs disagree. Making `OrderView` read `RUBRIC` is a fair first job
after the walkthrough. Changing a rubric item's `id` loses everyone's ticks for it;
changing a template key makes TEMPLATE fill nothing.

## 7. Export reads storage, not the screen: `src/export/exporters.ts`

`exportText(view)` and `exportPdf(view)` are the entry points. `orderDoc()`,
`analyzeDoc()`, `toolsDoc()` and `guideDoc()` build a `Doc` from `readNote` and friends,
never from React state; CASEVAC goes to `downloadCasevacPdf` in
`src/casevac/exportSheet.tsx`. Checklists arrive through `CHECKLIST_KEYS` in
`src/lib/checklists.ts`, so a key rename is a compile error rather than six empty lists.
All PDF text passes `pdfSafe` (`src/lib/pdfText.ts`) because jsPDF's built-in fonts only
know WinAnsi, and the file leaves through `saveBlob`. Reading storage makes the export
identical whether or not the tab is open, and equal to what was saved. The price is a
rule: every new note field goes into the matching `*Doc()` builder, or it is silently
missing from the PDF and the copied text. Text that skips `pdfSafe` prints arrows and
ticks as garbage.

## 8. Doctrine becomes math: `src/casevac/model.ts`, then `geo.ts` and `hlz.ts`

`CasevacPlan` is the planner's whole document: `v: 1`, the `hlz`, `ccp` and `route` sheets,
the paragraph 4.a fields and the `nineLine`. `savePlan` writes it under `casevac-plan`;
`loadPlan` reads it through `normalizePlan`, which checks every field against
`defaultPlan()`, drops bad list entries, clamps coordinates, makes ids unique and returns
null for anything that is not a v1 plan. Background images sit under `casevac-bg-<sheet>`
and pass `normalizeBackground`. Everything from outside, whether storage, a `#cv=` link
(`handoff.ts`), a plan file or a backup, goes through those two functions. `geo.ts` fixes
the coordinates: meters, x east, y north, origin at the sheet's reference grid.
`parseMgrs`, `offsetMgrs` and `gridDelta` work on the MGRS digits directly;
`northReference` gives the G-M angle as WMM declination (`geomagnetism`) minus
`gridConvergence`; `pts()` flips y because SVG is y-down. `computeHlz` in `hlz.ts` lays
out landing points by `lpDiameter`, the zone and corridors, an `ObstacleCheck` per obstacle
against `OBSTACLE_RATIO` (10 m of distance per 1 m of height) and the `WindCheck`
components; `hlzFindings` turns them into ok, warn and bad lines. Tests sit next to each
file. A field added to `CasevacPlan` but not to `normalizePlan` is dropped on every load. A
sign flip or a change to the `gm` formula moves every arrow and label. A change to the LP
table or the 10:1 ratio changes what the app tells someone is safe to land on; the tests
exist for that.

## 9. One build, two containers: `scripts/ios-device.sh`, `capacitor.config.ts`, `tools/serviceWorker.ts`

`npm run build` writes `dist/` and both products come from it. For the website,
`tools/serviceWorker.ts` is a Vite plugin that emits `dist/sw.js`: a `VERSION` hash of the
file list, the `PRECACHE` list of every built file, and the worker in `tools/sw.js`.
`src/main.tsx` registers it in production builds only and never in the app; the page is
network-first and hashed assets cache-first, so the site is current online and opens
offline after one visit. For the iPhone, `capacitor.config.ts` names the app
(`com.aarzamen.opord`) and points `webDir` at `dist`; `scripts/ios-device.sh` reads the
team id from `$OPORD_TEAM_ID` or the gitignored `ios/signing.local`, picks a device with
`xcrun devicectl`, runs `npm run build` and `npx cap sync ios`, builds Release with
`xcodebuild`, installs and launches. The build stamp tells the copies apart:
`vite.config.ts` defines `__BUILD__` (version, short commit plus `+dirty` if uncommitted,
branch, UTC time), `buildStamp()` prefixes "iOS app" or "web", and `App.tsx` prints it
under every tab; it is how the live site was found to be behind `main`. Register the worker
in dev and it serves stale modules. A cache name that does not change per deploy pins
users to an old build. `base: './'` in `vite.config.ts` is what lets `dist/` run under a
subpath on ChatGPT Sites; `/` breaks the deploy. Build from Xcode without `npm run build`
and `npx cap sync ios` and the phone carries the old bundle. Commit `ios/signing.local` and
the team id is public.
